# 1. Общая концепция приложения

## 1.1. Название проекта

**MICHI（道）** — «путь». Метафора продукта: обучение как дорога от станции N5 до станции N1, визуализированная как путь через Японию (Окинава → Хоккайдо). Tagline: **«Твой путь к японскому. От нуля до N1»**.

## 1.2. Целевая аудитория

| Сегмент | Описание | Доля | Ключевая потребность |
|---|---|---|---|
| **Начинающие с нуля** | 16–35 лет, интерес через аниме/мангу/игры/J-pop | ~55% | Низкий порог входа, быстрый видимый прогресс, развлекательный формат |
| **Готовящиеся к JLPT** | Студенты, планирующие учёбу/работу в Японии | ~25% | Структурированная подготовка к конкретному уровню, пробные тесты, прогноз готовности |
| **«Возвращенцы»** | Учили раньше, забросили, хотят восстановить | ~10% | Диагностика остаточных знаний, адаптивный старт не с нуля |
| **Профессионалы** | IT-специалисты, бизнес, туризм | ~7% | Тематические модули (бизнес-кейго, IT-лексика), гибкий график |
| **B2B** | Языковые школы, корпорации с релокацией в Японию | ~3% | Групповое управление, отчётность, корпоративные лицензии |

География запуска: RU/CIS + EN-рынок (интерфейс RU/EN, далее ES/PT/DE).

## 1.3. Основные сценарии использования

**US-1. Ежедневная сессия (core loop, 10–25 мин).** Пользователь открывает приложение → экран «Сегодня»: очередь SRS-повторений (вокабуляр + кандзи) → новый урок из текущего юнита → ежедневные задания → итоговый экран с XP и прогнозом. Цель: завершаемая сессия за время поездки в метро.

**US-2. Старт с нуля.** Онбординг → выбор цели (хобби / JLPT / переезд) и темпа (5/10/20/40 мин в день) → плейсмент-тест (пропускаемый) → первый урок хираганы в первые 90 секунд после установки.

**US-3. Подготовка к JLPT.** Пользователь выбирает целевой уровень и дату экзамена → система строит обратный план (сколько слов/кандзи/грамматики в неделю) → еженедельные мини-тесты в формате JLPT → полноразмерные пробные экзамены с таймером → прогноз балла.

**US-4. Разговорная практика с ИИ.** Пользователь открывает «Кайва-додзё» → выбирает сценарий (кафе, аэропорт, собеседование) → голосовой/текстовый диалог с AI-репетитором, ограниченным лексикой уровня пользователя → разбор ошибок после сессии.

**US-5. Словарь как утилита.** Быстрый поиск слова/кандзи (ромадзи, кана, рукописный ввод, радикалы, фото через OCR) → карточка слова → кнопка «добавить в SRS». Работает офлайн.

**US-6. Восстановление после перерыва.** Пользователь возвращается после 3+ недель → система не вываливает 800 просроченных карточек, а предлагает «режим восстановления»: диагностический срез → реструктуризация очереди → щадящий план на 2 недели.

## 1.4. Конкурентный анализ

| Продукт | Сильные стороны | Слабые стороны (наша возможность) |
|---|---|---|
| **Duolingo** | Геймификация, привычка, огромная база пользователей | Японский курс поверхностный: слабая грамматика, нет системной работы с кандзи, нет подготовки к JLPT, перевод-центричная методика |
| **WaniKani** | Лучшая мнемоническая система кандзи, строгий SRS | Только кандзи/вокабуляр; нет грамматики, аудирования, разговора; принудительный темп; только EN |
| **Anki** | Идеальный SRS (FSRS), гибкость | Это инструмент, а не курс: нулевой UX для новичка, нужно самому искать колоды, нет проверки навыков |
| **LingoDeer** | Хорошая грамматика для азиатских языков | Слабая SRS-система, мало контента после N4, нет ИИ, устаревший UX |
| **Bunpro** | Системная грамматика по JLPT | Только грамматика, требует внешних ресурсов |
| **Busuu** | Проверка заданий носителями | Японский — не фокусный язык, слабые кандзи |
| **Renshuu** | Глубина контента | Перегруженный интерфейс, высокий порог входа |

**Позиционирование MICHI:** единственное приложение, объединяющее (а) полный структурированный курс N5→N1, (б) Anki-класс SRS на алгоритме FSRS, (в) WaniKani-класс работу с кандзи и (г) ИИ-репетитора для продуктивных навыков — в одном продукте с Duolingo-классом UX.

## 1.5. Уникальные преимущества (USP)

1. **Полный путь N5→N1 в одном продукте** — конкуренты покрывают либо начало, либо один навык.
2. **FSRS-алгоритм повторений** с персональными параметрами забывания — научно обоснованная эффективность Anki без боли Anki.
3. **AI-репетитор «Сэнсэй»**: объяснение ошибок на родном языке пользователя, генерация упражнений под слабые места, разговорная практика с контролем уровня лексики.
4. **Рукописный ввод кандзи** с проверкой порядка черт на всех платформах.
5. **Единый граф знаний**: каждое слово связано с кандзи, кандзи — с радикалами, грамматика — с примерами из выученной лексики. Пользователь не встречает в примерах незнакомых элементов («принцип i+1»).
6. **Прогноз готовности к JLPT** на основе реальной статистики запоминания, а не пройденных уроков.
7. **Честный офлайн-режим**: уроки, SRS и словарь работают без сети, синхронизация — при подключении.

# 2. Система обучения

Методическая основа: комбинация структурного подхода (грамматическая прогрессия в духе «Минна-но нихонго» / Genki), comprehensible input (Krashen, i+1), интервальных повторений (Ebbinghaus → FSRS) и активного воспроизведения (active recall, testing effect). Каждый учебный элемент проходит цикл: **знакомство → распознавание → воспроизведение → применение в контексте → автоматизация через SRS**.

## 2.1. Хирагана

- **Объём:** 46 базовых знаков + дакутэн/хандакутэн (が, ぱ…) + ёон (きゃ, しゅ…) + сокуон (っ) + долгие гласные. Итого ~104 графемы/комбинации.
- **Порядок введения:** по рядам годзюон (あ→か→さ→た→な→は→ま→や→ら→わ), 1 ряд = 1 микроурок (5–7 мин). Полный курс — 10–14 дней при темпе 2 ряда в день.
- **Методика урока:** анимация порядка черт → мнемоническая картинка (あ — «антенна на крыше») → трассировка пальцем по контуру → написание по памяти → распознавание среди похожих → чтение слогов на скорость → чтение первых настоящих слов из уже известных знаков.
- **Особый блок «ловушки»:** парные тренировки визуально похожих знаков (ぬ/め, わ/れ/ね, は/ほ, さ/ち).
- **Критерий завершения:** распознавание любого знака < 2 сек с точностью ≥ 95%, написание по памяти с корректным порядком черт.
- После завершения хираганы ромадзи **полностью отключается** в интерфейсе курса (опция вернуть — в настройках, с предупреждением).

## 2.2. Катакана

- Вводится **после** хираганы (чтобы избежать интерференции), курс 7–10 дней.
- Та же механика + специфика: упор на гайрайго (コーヒー, インターネット) — катакана сразу даёт «полезные» слова; правило долготы через ー; расширенные комбинации для заимствований (ファ, ティ, ヴ).
- Отдельный тренажёр «катакана-ад»: シ/ツ, ソ/ン, ク/ワ/フ — обязательные дриллы до точности ≥ 95%.
- Постоянная поддержка: катакана-слова подмешиваются в SRS навсегда, т.к. катакана забывается быстрее хираганы.

## 2.3. Кандзи

Полная подсистема описана в [разделе 6](#6-работа-с-кандзи). Принципы:

- **Порядок изучения** — не школьный японский (кёику), а частотно-компонентный: сначала графически простые и частотные знаки и компоненты, из которых собираются сложные (методика RTK/WaniKani, но с привязкой к лексике текущего уровня JLPT).
- Кандзи никогда не учится изолированно: знак вводится **вместе с 2–4 словами**, в которых он реально употребляется на текущем уровне.
- Три отслеживаемых навыка на каждый кандзи, каждый — отдельная SRS-карточка: значение (распознавание), чтения в словах (он/кун в контексте), написание (рукописный ввод).

## 2.4. Грамматика

- **Единица контента — «грамматическая точка»** (grammar point): конструкция с формулой образования, значением, регистром, типичными ошибками, 8–15 примерами и связями («не путать с…», «требует знания…»).
- **Подача:** короткое интерактивное объяснение (max 4 экрана: формула → 3 примера с разбором → сравнение с похожей конструкцией → типичная ошибка) → серия упражнений от распознавания к продукции → конструкция попадает в грамматический SRS (карточка = «собери предложение с этой конструкцией»).
- **Прогрессия** строится на графе зависимостей: ～てもいい недоступна, пока не освоена て-форма. Граф отображается пользователю как «дерево навыков».
- Все примеры используют **только изученную лексику** (контролируется автоматически по графу знаний).
- ИИ-репетитор отвечает на вопросы «почему здесь は, а не が» по любому встреченному предложению.

## 2.5. Лексика

- **Источник:** частотные списки + тематическая релевантность JLPT. Слово = запись со чтением, питч-акцентом, переводами, частеречной разметкой, 3+ примерами, аудио (носитель, м/ж голоса), связями с кандзи и синонимами.
- **Введение слова:** в составе урока в контексте (диалог/текст) → карточка слова → упражнения распознавания → продукции → в SRS.
- **Направления карточек:** JP→RU (распознавание) и RU→JP (воспроизведение) — раздельные SRS-карточки с независимыми интервалами; аудио→значение — третий тип для слов с коварным чтением.
- Тематические **пакеты лексики** (еда, IT, путешествия, аниме-лексика) — подключаемые модули поверх основного курса.

## 2.6. Аудирование

- **Уровни сложности аудио:** студийная запись с нормальной скоростью → естественная скорость → фоновый шум/несколько голосов (N2–N1).
- **Форматы:** диктанты, минимальные пары (病院/美容院, おばさん/おばあさん), понимание диалогов с вопросами, JLPT-формат (выбор ответа по аудио без текста вопроса), извлечение чисел/дат/имён.
- **Регулировка скорости:** 0.7× / 0.85× / 1.0× / 1.25× без изменения тона (time-stretch).
- Каждое слово и предложение в приложении озвучено; TTS (нейронный, ja-JP) — только для ИИ-генерируемого контента, основной курс — записи дикторов.
- **Подкаст-режим:** 3–5-минутные истории на изученной лексике (comprehensible input) с синхронной подсветкой текста.

## 2.7. Произношение

- **Фокус:** мора-ритм (не слоговой), долгие/краткие гласные (おばさん≠おばあさん), сокуон, питч-акцент (показывается схемой над каждым словом: 平板/頭高/中高/尾高), редукция гласных (です→[des]).
- **Механика проверки:** запись голоса → ASR (распознавание речи ja-JP) → сравнение с эталоном: точность фонем, длительность мор, контур питча → оценка 0–100 с подсветкой проблемных мор.
- **Shadowing-тренажёр:** проигрывание фразы → одновременное повторение → визуальное наложение волновой формы и питч-контура пользователя на эталон.
- Минимальный порог — «понятность» (intelligibility), а не «акцент»: критерии проверки калибруются, чтобы не фрустрировать.

## 2.8. Чтение

- **Градуированные тексты** (graded readers) на каждый уровень: N5 — 2–4 предложения с фуриганой везде; N3 — абзацы, фуригана только над неизученными кандзи; N1 — газетные статьи и фрагменты художественных текстов без фуриганы.
- **Умная фуригана:** показывается только над кандзи, которые пользователь ещё не освоил в SRS (порог — stability карточки). Тап по любому слову — всплывающий словарь с кнопкой «в SRS».
- **Типы заданий:** вопросы на понимание, поиск информации (расписание, объявление — формат JLPT 情報検索), выбор заголовка, восстановление порядка абзацев, скорочтение с измерением знаков/мин.
- Вертикальное письмо (縦書き) вводится с N3 как опция отображения текстов.

## 2.9. Письмо

- **Графика:** рукописный ввод каны и кандзи (палец/стилус/мышь) с проверкой порядка, направления и количества черт (см. 6.7).
- **Продукция:** от подстановки (N5) → составление предложений из заданных слов → ответы на вопросы свободным текстом → короткие сочинения (N3+: 100–200 знаков, N1: 400+) → деловое письмо и кейго (N2+).
- Свободные письменные ответы проверяет ИИ-модуль: грамматика, естественность, соответствие заданию, регистр — с построчным разбором (см. раздел 7).
- Набор текста: обучение вводу через IME с самого начала (флик-клавиатура на мобильных — отдельный тренажёр, это реальный навык для жизни в Японии).

# 3. Учебный план по уровням JLPT

Структура курса: **Уровень → Юниты (тематические блоки, 8–12 уроков) → Уроки (10–20 мин)**. Урок = диалог/текст → новая лексика → грамматика → упражнения → мини-итог. Каждый 5-й урок — повторительный, каждый юнит закрывается тестом-«воротами» (gate test, порог 80%).

Объёмы лексики и кандзи указаны **накопительно** (включая предыдущие уровни).

## 3.1. JLPT N5 — «Фундамент» (3–5 месяцев при 20 мин/день)

| Параметр | Значение |
|---|---|
| Слова | ~800 (накопительно 800) |
| Кандзи | ~110 |
| Кана | хирагана + катакана полностью |
| Юнитов / уроков | 12 юнитов / ~120 уроков |
| Грамматических точек | ~80 |

**Темы грамматики:** структура AはBです; частицы は・が・を・に・で・へ・と・も・の・から・まで・よ・ね; указательные こ/そ/あ/ど; счёт и счётные слова (人, 本, 枚, 個, つ); существование いる/ある; настояще-будущее и прошедшее время (ます/ました); отрицание; い- и な-прилагательные (включая прошедшее время прилагательных); наречия степени; て-форма и её базовые применения (～てください, ～てもいい, ～てはいけない, ～ています); простая форма глаголов (словарная, ない, た); ～たい; ～ましょう/～ませんか; ～が好き/上手; сравнения (より, のほうが, いちばん); ～から (причина); ～とき; ～たり～たり; ～たことがある; ～つもり; ～でしょう.

**Типы упражнений:** распознавание/написание каны, выбор перевода, сопоставление, аудио-выбор, сборка предложений из блоков, тест на частицы (одиночный пропуск), трассировка кандзи, картинка→слово, простые диктанты (слово/короткая фраза), диалоги с подстановкой реплик.

## 3.2. JLPT N4 — «Самостоятельность» (4–6 месяцев)

| Параметр | Значение |
|---|---|
| Слова | ~1 500 (+700) |
| Кандзи | ~300 (+190) |
| Юнитов / уроков | 12 юнитов / ~130 уроков |
| Грамматических точек | ~110 |

# 4. Система интервальных повторений (SRS)

## 4.1. Выбор алгоритма: FSRS

Используем **FSRS (Free Spaced Repetition Scheduler) v5** — современный алгоритм Anki, статистически превосходящий SM-2. Лицензия открытая, есть референсные реализации (TypeScript `ts-fsrs`, Rust `fsrs-rs`).

Каждая карточка описывается тремя параметрами (DSR-модель):

| Параметр | Смысл |
|---|---|
| **D — Difficulty** (1–10) | Внутренняя сложность карточки: насколько медленно растёт её стабильность |
| **S — Stability** (дни) | Интервал, за который вероятность вспоминания падает до 90% |
| **R — Retrievability** (0–1) | Текущая вероятность успешного вспоминания |

Кривая забывания: `R(t) = (1 + FACTOR · t/S)^DECAY` (степенная, параметры FSRS-5). Очередной показ назначается на момент, когда R опустится до **целевого уровня удержания** (desired retention, по умолчанию 0.9; настраивается пользователем в диапазоне 0.80–0.95 с показом trade-off «время занятий ↔ % запоминания»).

После каждого ответа S и D пересчитываются по формулам FSRS с 19 весовыми коэффициентами. Раз в 2 недели (и по запросу) запускается **оптимизатор**: персональные веса пересчитываются по полной истории ответов пользователя (фоновая задача на сервере). Новые пользователи стартуют с глобальными весами, обученными на агрегированных данных всех пользователей.

## 4.2. Состояния карточки и оценка сложности

Жизненный цикл: **New → Learning → Review ⇄ Relearning**.

- **Learning** (внутридневные шаги): 1 мин → 10 мин → выпуск в Review с начальной стабильностью по FSRS.
- Ответ в Review — **4 кнопки**: `Снова` (Again) / `Трудно` (Hard) / `Хорошо` (Good) / `Легко` (Easy). Под кнопками показывается прогноз следующего интервала («Хорошо → 6 дн»).
- Для упражнений с автоматической проверкой (ввод, рукописный кандзи) оценка проставляется автоматически: ошибка → Again; верно с подсказкой/долго (> p75 времени пользователя) → Hard; верно → Good; верно быстро и без колебаний (< p25) → Easy. Ручные кнопки остаются для карточек-флэшкарт.
- `Снова` переводит карточку в Relearning (шаг 10 мин) и снижает стабильность по формуле post-lapse FSRS (не обнуляет!).
- **Пиявки (leeches):** ≥ 6 ошибок в Review → карточка помечается, система предлагает: мнемонику от ИИ, разбивку на компоненты, сравнение с конфузером (слово, с которым путает, определяется по логу ошибок) или заморозку.

## 4.3. Прогноз забывания

- Для каждой карточки хранится текущая R — пересчитывается лениво при чтении.
- **Экран «Прогноз»:** график на 30/90 дней — сколько карточек упадёт ниже порога удержания, если не заниматься; ожидаемая ежедневная нагрузка повторений.
- **Симулятор:** «что будет, если я снижу retention до 0.85 / добавлю 5 новых слов в день» — пересчёт прогнозной нагрузки.
- Прогноз используется ИИ-планировщиком: если до экзамена 60 дней, а очередь растёт быстрее, чем усваивается, система предлагает снизить поток новых карточек.

## 4.4. Ежедневные лимиты

| Настройка | По умолчанию | Диапазон |
|---|---|---|
| Новые карточки/день | 12 | 0–50 (free: max 20) |
| Повторения/день | 150 | 50–∞ (free: 100) |
| Порядок очереди | просроченные → по убыванию риска забывания → новые | — |

- Лимит новых карточек **автоадаптивный**: если доля верных ответов за последние 7 дней < 75% или средняя длина сессии превышает целевую на 50%, система предлагает временно снизить поток новых.
- **Режим восстановления** после перерыва: просроченная очередь сортируется по R; карточки с R < 0.3 массово переводятся в Relearning порциями по 20/день; пользователю показывается план «разгребём за N дней».
- Подача внутри сессии перемешивается по типам (кандзи/слова/грамматика) и направлениям, родственные карточки (слово и его кандзи) разносятся минимум на 3 позиции («burying»).

## 4.5. Статистика запоминания

- **True Retention:** фактический % вспоминания в Review за день/неделю/месяц, в разрезе типов карточек.
- **Карта стабильности:** распределение карточек по интервалам (гистограмма: сколько карточек «живут» < 1 нед / 1–4 нед / 1–6 мес / > 6 мес).
- Календарь-heatmap повторений (как в GitHub/Anki).
- Среднее время ответа по типам, динамика D (становится ли материал субъективно легче).
- Список «самых трудных карточек» с действиями (мнемоника/заморозка/сброс).
- Журнал каждого ответа сохраняется навсегда (таблица `reviews`) — это сырьё для оптимизатора FSRS и аналитики.

# 5. Типы упражнений

58 типов. Формат описания: **Цель | Механика | Критерии проверки**. Каждый тип имеет машинное имя (`exercise_type`) для БД и генераторов.

## 5.1. Кана (7)

1. **`kana_recognition` Распознавание каны.** Цель: связь графема→звук. Механика: показан знак, выбор чтения из 4 (на слух или ромадзи). Критерии: точность; время < 2 с для «автоматизма».
2. **`kana_reverse` Звук → кана.** Цель: связь звук→графема. Механика: проигрывается слог, выбор знака из 4–6 визуально похожих. Критерии: точность, устойчивость к конфузерам.
3. **`kana_tracing` Написание каны.** Цель: моторика и порядок черт. Механика: трассировка по контуру → написание по памяти на пустом поле. Критерии: распознавание формы + порядок и направление черт (см. 6.7).
4. **`kana_word_build` Сборка слова из каны.** Цель: чтение слогами. Механика: аудио слова → собрать из плиток-знаков. Критерии: точная последовательность, включая っ/ー/ёон.
5. **`kana_dakuten` Дакутэн-различение.** Цель: озвончение. Механика: аудио → выбрать は/ば/ぱ-вариант. Критерии: точность ≥ 90% на блок.
6. **`kana_speed` Скоростное чтение.** Цель: автоматизация. Механика: тайм-атака — 30 знаков подряд, ввод ромадзи. Критерии: знаков/мин + точность; результат в лидерборд.
7. **`kana_twins` Парные ловушки.** Цель: различение シ/ツ, ソ/ン, ぬ/め и т.п. Механика: серия бинарных выборов с нарастающим темпом. Критерии: точность ≥ 95%, иначе блок повторяется.

## 5.2. Лексика (10)

8. **`vocab_choice` Выбор перевода.** Цель: пассивное узнавание. Механика: слово (кандзи+фуригана по уровню) → 4 варианта перевода, дистракторы — семантически близкие из изученного. Критерии: точность; выбор дистрактора логируется как «конфузия».

10. **`vocab_input` Ввод слова.** Цель: активное воспроизведение. Механика: перевод/картинка → ввод каной (IME-набор). Критерии: точное совпадение чтения; орфографические близкие варианты (длина гласной) → «почти, проверь долготу» с оценкой Hard.
11. **`vocab_match` Сопоставление пар.** Цель: быстрое связывание. Механика: 5 слов ↔ 5 переводов, перетаскивание/тапы. Критерии: все пары; ошибки снижают XP, но задание завершается.
12. **`vocab_audio` Аудио → слово.** Цель: распознавание на слух. Механика: аудио → выбор из 4 написаний/переводов. Критерии: точность; повтор аудио не более 2 раз для полного балла.

14. **`vocab_word_to_pic` Слово → картинка.** Цель: то же, обратное направление. Механика: слово → выбор 1 из 4 изображений. Критерии: точность.
15. **`vocab_synonym` Синонимы/антонимы.** Цель: семантическая сеть (N3+). Механика: слово → найти синоним/антоним из 4. Критерии: точность.
16. **`vocab_odd_one` Лишнее слово.** Цель: категоризация. Механика: 4 слова, одно из другой категории. Критерии: точность + время.
17. **`vocab_cloze` Контекстный выбор.** Цель: употребление, коллокации. Механика: предложение с пропуском → 4 слова, подходит одно (остальные грамматически валидны, но семантически ломают смысл). Критерии: точность; объяснение ИИ при ошибке.

31. **`register_transform` Трансформация регистра.** Цель: вежливая ↔ простая ↔ кейго. Механика: предложение → переписать в целевом регистре (ввод). Критерии: проверка по списку валидных форм + ИИ-фоллбэк для свободных вариантов.
32. **`error_hunt` Поиск ошибки.** Цель: мониторинг/самокоррекция. Механика: предложение с 1 ошибкой → тапнуть ошибочный фрагмент → выбрать исправление. Критерии: найдено место + верное исправление (2 балла раздельно).
33. **`sentence_join` Соединение предложений.** Цель: связность. Механика: 2 простых предложения + целевой смысл («причина») → выбрать/ввести связку (から/ので/のに). Критерии: точность + регистр.
34. **`grammar_cloze` Грамматический cloze.** Цель: комплексное применение. Механика: текст 3–5 предложений с 4–6 пропусками (банк ответов). Критерии: все пропуски; частичный зачёт.
35. **`counter_choice` Счётные слова.** Цель: классификаторы. Механика: «3 (карандаша)» → выбор 本/枚/個/匹 + верное чтение числа (さんぼん!). Критерии: классификатор и фонетика числа.
36. **`jlpt_star` «Звёздочка» (文の組み立て).** Цель: формат JLPT. Механика: предложение с 4 пустыми слотами, один помечен ★ → расставить 4 фрагмента, ответ — что попало в ★. Критерии: позиция ★ верна.

## 5.5. Аудирование (7)

37. **`dictation` Диктант.** Цель: связь звук→текст. Механика: аудио (слово→фраза→предложение по уровню) → ввод текста. Критерии: посимвольное сравнение с нормализацией (кандзи/кана-варианты равноценны); diff подсвечивается.
38. **`minimal_pairs` Минимальные пары.** Цель: фонематический слух. Механика: аудио → выбор из 2–3 (病院/美容院, 来て/切って). Критерии: точность ≥ 85% на блок.
39. **`audio_question` Аудио-вопрос.** Цель: быстрое понимание. Механика: вопрос звучит (без текста!) → 3 варианта ответа текстом/аудио. Критерии: точность; формат JLPT 即時応答.
40. **`dialogue_comprehension` Понимание диалога.** Цель: глобальное понимание. Механика: диалог 20–60 с → 2–4 вопроса (кто/где/что решили). Критерии: точность; транскрипт открывается только после ответа.
41. **`dialogue_order` Порядок реплик.** Цель: логика диалога. Механика: реплики перемешаны → восстановить порядок, прослушать результат. Критерии: точная последовательность.
42. **`shadowing` Shadowing.** Цель: беглость + слух. Механика: фраза → одновременное повторение с записью → наложение питч-контуров. Критерии: совпадение ритма/мор ≥ порога; мягкая оценка (см. 2.7).
43. **`info_extract` Извлечение данных.** Цель: селективное слушание. Механика: объявление/прогноз погоды → заполнить поля (время, цена, платформа). Критерии: точность каждого поля.

## 5.6. Произношение (4)

44. **`pronounce_repeat` Повтор за диктором.** Цель: артикуляция. Механика: слово/фраза → запись → ASR-оценка фонем и длительности мор. Критерии: оценка ≥ 60 — зачёт; подсветка проблемных мор.
45. **`pitch_pattern` Питч-акцент.** Цель: акцентные типы. Механика: аудио слова → выбрать схему (平板/頭高/中高/尾高) из визуальных контуров. Критерии: точность.
46. **`read_aloud` Чтение вслух.** Цель: связь текст→речь. Механика: предложение на экране → прочитать → ASR-сверка с текстом. Критерии: ≥ 90% слов распознано верно, паузы в допустимых местах.
47. **`mora_length` Долгота.** Цель: おばさん vs おばあさん. Механика: произнести оба слова пары → система сверяет относительную длительность. Критерии: различие длительностей в нужную сторону.

## 5.7. Чтение (6)

48. **`reading_comprehension` Текст + вопросы.** Цель: понимание. Механика: градуированный текст → 2–5 вопросов (факт/вывод/отношение автора). Критерии: точность; вопросы «на вывод» весят больше.
49. **`paragraph_order` Порядок абзацев.** Цель: связность текста. Механика: перемешанные абзацы → восстановить. Критерии: последовательность; подсчёт инверсий для частичного балла.
50. **`info_search` Поиск информации.** Цель: JLPT 情報検索 / реальная жизнь. Механика: афиша/расписание/меню → вопрос («во сколько последний поезд до…») → ответ. Критерии: точность; лимит времени.
51. **`headline_choice` Заголовок к тексту.** Цель: главная мысль. Механика: текст → 4 заголовка. Критерии: точность.
52. **`speed_reading` Скорочтение.** Цель: беглость. Механика: текст с таймером → вопросы после. Критерии: знаков/мин при понимании ≥ 70%; динамика — в аналитику.
53. **`furigana_off` Чтение без фуриганы.** Цель: проверка реальной автономности. Механика: знакомый по уровню текст с выключенной фуриганой → пометить слова, которые не смог прочитать (честная самооценка) + выборочная проверка чтений вводом. Критерии: совпадение самооценки с проверкой → калибровка SRS.

## 5.8. Письмо и продукция (5)

54. **`translate_input` Перевод предложения.** Цель: активная грамматика+лексика. Механика: RU→JP ввод свободным текстом. Критерии: каскад — точное совпадение с эталонами → структурное сравнение → ИИ-оценка (приемлемо/ошибки с разбором).
55. **`guided_writing` Предложение по опорным словам.** Цель: управляемая продукция. Механика: даны 3 слова + конструкция → составить предложение. Критерии: ИИ проверяет использование всех опор + грамматичность.
56. **`free_answer` Свободный ответ.** Цель: коммуникация. Механика: вопрос («Что ты делал в выходные?») → ответ 1–3 предложения. Критерии: ИИ — релевантность, грамматика, естественность; оценка + 2 конкретных улучшения.
57. **`essay` Сочинение.** Цель: связный текст (N3+). Механика: тема + требования (объём, конструкции) → текст → ИИ-оценка по рубрикам (содержание/грамматика/лексика/связность, 0–5 каждая). Критерии: рубрики + построчные комментарии; история версий.
58. **`ai_roleplay` Ролевой диалог с ИИ.** Цель: разговорная практика. Механика: сценарий с целью («забронируй столик на 19:00 на четверых») → текстовый/голосовой диалог; ИИ играет роль и держит лексику в рамках уровня. Критерии: достигнута ли цель сценария + пост-разбор ошибок; оценка не блокирует прогресс.

**Антиповторяемость:** движок упражнений выбирает тип по матрице «учебная цель × стадия освоения × последние N типов» — один и тот же элемент тренируется разными типами, тип не повторяется чаще 2 раз подряд.

# 6. Работа с кандзи

## 6.1. Данные

Базовые датасеты: **KANJIDIC2** (чтения, значения, уровни), **KanjiVG** (векторные черты с порядком — SVG, лицензия CC BY-SA), **JMdict** (лексика), частотные списки (газетный корпус + субтитры). Поверх — редакторская обработка: ключевые значения на русском, мнемоники, отбор примеров по уровням.

## 6.2. Порядок черт

- Каждый кандзи — анимация поэтапного написания (рендер из KanjiVG): черты появляются последовательно, текущая черта подсвечена, направление показано движущейся точкой.
- Правила порядка (сверху вниз, слева направо, горизонталь раньше пересекающей вертикали и т.д.) вводятся явно как мини-уроки на первых 20 кандзи, далее — закрепляются практикой.
- Режимы: просмотр анимации → трассировка по полупрозрачному контуру → написание по памяти с сеткой 米 → написание без сетки.

## 6.3. Радикалы и компоненты

- Используется прагматичная система **~250 компонентов** (214 канси-радикалов + частотные фонетики и формы), каждый с русским именем-образом (氵— «вода», 亻— «человек сбоку»).
- Компонент вводится **до** первого кандзи, который его использует. Карточка кандзи показывает разбор: 語 = 言 (слова) + 五 (пять) + 口 (рот).
- **Фонетические подсказки:** для серий типа 青→晴・清・精 система явно показывает «компонент 青 часто читается セイ» — это ускоряет освоение онъёми на сотнях знаков.
- Поиск по радикалам в словаре: мультивыбор компонентов → сужающийся список кандзи.

## 6.4. Онъёми и кунъёми

- Принцип: **чтения учатся через слова, не списками.** Карточка кандзи показывает чтения, но SRS-проверка чтений всегда идёт в контексте слова (тип 20).
- Приоритизация: сначала самое частотное чтение в самом частотном слове уровня; редкие чтения (нанори, исключения) — пометкой «позже».
- Цветовое кодирование во всём приложении: онъёми — катакана + один цвет, кунъёми — хирагана + другой; рэндаку и фонетические сдвиги (学+校=がっこう) подсвечиваются с пояснением.
- Исключительные чтения (熟字訓: 今日, 大人, 時計) помечаются как «слово-картинка — читается целиком».

## 6.5. Примеры слов

- На каждый кандзи — 2–4 слова при введении (только из лексики текущего/пройденного уровня), полный список — в словарной карточке.
- Каждое слово-пример: чтение, питч, перевод, аудио, предложение-пример с переводом.
- Связность графа: из слова → ко всем его кандзи; из кандзи → ко всем изученным словам с ним; «этот знак встретился вам в 7 словах» — экран знакомых контекстов.

## 6.6. Мнемоники

- Редакторская мнемоника на **значение** (история из образов компонентов) и на **чтение** (звуковая ассоциация на русском: 九 キュウ — «девять кью на бильярде»).
- Пользователь может: написать свою мнемонику (приватная), посмотреть топ мнемоник сообщества (с голосованием), запросить **персональную мнемонику у ИИ** (учитывает родной язык и уже известные пользователю образы компонентов).
- Для пиявок (4.2) мнемоника предлагается автоматически.

## 6.7. Система проверки рукописного написания

Технология: **онлайн-распознавание черт** (по траекториям, не по растру).

Пайплайн проверки:
1. Захват черт: последовательность точек с таймстемпами (палец/стилус/мышь).
2. Нормализация: масштаб, сглаживание (фильтр Дугласа–Пекера).
3. Сопоставление с эталоном KanjiVG: количество черт → порядок → направление каждой черты → форма (DTW-расстояние по траектории) → взаимное расположение.
4. Вердикт по уровням строгости:

| Режим | Допуски |
|---|---|
| Обучение (первые показы) | подсказка-контур, прощается порядок, проверяется форма |
| Стандарт | форма + число черт + порядок; направление — предупреждение |
| Экзамен (gate-тесты) | всё строго, без подсказок |

5. Фидбек: ошибочная черта подсвечивается красным с анимацией правильной; типовые диагнозы текстом («эта черта пишется сверху вниз», «здесь две черты, а не одна»).

Fallback: для свободного ввода в словаре — рекуррентная модель распознавания рукописного кандзи (по типу Google handwriting), работающая на устройстве (TFLite/Core ML), офлайн.

# 7. ИИ-функции: AI-репетитор «Сэнсэй»

## 7.1. Архитектура ИИ-модуля

- **LLM-провайдер:** Claude API (Anthropic) как основной — сильное владение японским и педагогичные объяснения; модельный роутинг: лёгкие задачи (короткие подсказки, классификация ошибок) → Haiku-класс; разбор сочинений и диалоги → Sonnet/Opus-класс. Абстракция провайдера в коде (interface `LlmProvider`) для замены/добавления моделей.
- **RAG-слой:** векторный индекс по собственной базе грамматических точек, словарю и FAQ — ИИ объясняет в терминологии курса и ссылается на конкретные уроки («это конструкция из урока N4-3.2, вот ссылка»).
- **Контекст пользователя в каждом промпте:** уровень, изученные грамматики/лексика (компактный профиль), последние ошибки, родной язык. Это держит ответы в зоне i+1.
- **Гардрейлы:** системный промпт фиксирует роль (только обучение японскому), фильтр тем, лимит длины; ответы с японским текстом валидируются морфологическим анализатором (MeCab/Sudachi) на соответствие заявленному уровню лексики; модерация ввода.
- **Стоимость под контролем:** кэширование типовых объяснений (одна и та же ошибка в одном упражнении), prompt caching, лимиты запросов по тарифам, очередь с приоритетами.

## 7.2. Возможности

**1. Объяснение грамматики.** Кнопка «?» у любого предложения в приложении → разбор: пословный глоссинг, почему такая частица/форма, ссылка на урок. Follow-up вопросы в чате («а можно здесь сказать が?») — диалоговый контекст сохраняется в рамках сессии.

**2. Разбор ошибок.** После неверного ответа в любом упражнении: классификация ошибки (частица / спряжение / лексика / порядок слов / кана-орфография), объяснение в 2–3 предложения на родном языке, мини-правило, контрпример. Классификация пишется в БД → питает карту слабых мест (раздел 10).

**3. Генерация упражнений.** По слабым местам пользователя: ИИ генерирует предложения-задания, использующие проблемную грамматику + только изученную лексику → автоматическая валидация (морфоанализ, проверка лексики по графу знаний, проверка единственности ответа) → попадание в «персональный дрилл». Невалидные генерации отбрасываются; человеческой модерации требуют только жалобы.

**4. Создание диалогов.** Параметризуемые сценарии: тема, роли, регистр, целевые конструкции, длина. Используется в «Кайва-додзё» и в генераторе аудирования (TTS-озвучка двумя голосами).

**5. Проверка письменных ответов.** Пайплайн типов 54–57: эталонное сравнение → при несовпадении ИИ оценивает по рубрикам, возвращает JSON {оценка, ошибки[{фрагмент, тип, исправление, объяснение}], улучшенная версия}. UI рендерит построчный diff.

**6. Адаптация сложности.** Фоновый «педагогический планировщик»: еженедельный анализ статистики → рекомендации (снизить поток новых карточек, вернуться к юниту X, добавить аудирование) → пользователю показывается как «совет Сэнсэя» с кнопками принять/отклонить. Решения логируются для оценки эффективности рекомендаций.

**7. Разговорная практика.** Голосовой режим: ASR (ja-JP) → LLM (роль + уровень лексики + цель сценария) → TTS. Поддержка «спасательных» функций: «не понял — медленнее», «как сказать …?» (переключение на родной язык не ломает сессию). После сессии — отчёт: достижение цели, 3 главные ошибки, новые слова, которые пользователь пытался использовать → предложение добавить их в SRS.

## 7.3. Нефункциональные требования к ИИ

- Латентность: подсказки < 2 с (p95), разбор сочинения < 15 с, голосовой ход диалога < 2.5 с end-to-end.
- Все ИИ-ответы помечены как ИИ; кнопка «пожаловаться на ответ» с обязательным просмотром модерацией.
- Персональные данные в промпты не передаются (только анонимный учебный профиль).
- Деградация: при недоступности LLM приложение полностью функционально (ИИ-фичи скрываются, основной курс не зависит от ИИ).

# 8. Геймификация

Принцип: геймификация **поддерживает** учебное поведение (регулярность, объём, преодоление трудного), а не подменяет его. Никаких механик, наказывающих за честные ошибки в SRS.

## 8.1. Опыт и уровни

- **XP** за всё: упражнение 1–3 XP (×1.5 за безошибочную серию), урок 15–25 XP, SRS-сессия — по числу карточек, пробный тест 50–100 XP. XP за повторения не уступает XP за новое — чтобы не стимулировать гонку вперёд.
- **Уровень аккаунта** (1–100): кривая опыта квадратичная; уровни дают косметику и титулы (見習い «ученик» → 旅人 «странник» → 達人 «мастер»). Уровень ≠ языковой уровень, это «стаж пути».
- **Ранги пути:** карта Японии — продвижение по курсу открывает префектуры с открыточными иллюстрациями и культурными фактами (визуализация прогресса = метафора «мити»).

## 8.2. Серии дней (streak)

- День засчитан при выполнении **дневной цели** (настраиваемая: 10/20/40 XP или «закрыть SRS-очередь»).
- **Заморозки:** 2 шт. в месяц бесплатно, авто-применение; Premium — 4. Покупка за внутреннюю валюту — max 2/мес (анти-абьюз).
- «Восстановление серии» в течение 48 ч за валюту — один раз в 30 дней.
- Вехи серии (7/30/100/365 дней) → достижения + бонусы. Уведомление о сгорающей серии — не позднее 20:00 локального времени, тон — поддерживающий, без эмоционального шантажа.

## 8.3. Достижения (120+ при запуске)

Категории: путь (юниты/уровни), объём (1000 слов, 500 кандзи), мастерство (100 карточек со стабильностью > 6 мес), регулярность (серии), навыки (первый диалог с ИИ, 100 диктантов), скрытые/юмористические («Ночная сова» — занятие в 3:00; «シツ-мастер» — 50 верных различений подряд). Каждое: иконка, редкость (бронза/серебро/золото/легенда), XP-бонус.

## 8.4. Рейтинги

- **Еженедельные лиги** (по 30 человек схожей активности): Бронза→Серебро→Золото→Сапфир→Алмаз; топ-10 повышаются, низ — понижается. Рейтинг по XP с капом дневного учёта (защита от гринда).
- Опционально: лидерборды среди друзей; полное отключение соревновательности одним тумблером (для аудитории, которую лиги демотивируют).

## 8.5. Ежедневные и еженедельные задания

- 3 дневных квеста (ротация): «закрой 30 повторений», «пройди 1 урок», «10 минут аудирования», «выбей точность ≥ 90% в SRS». Награда: XP + валюта.
- Недельный квест-цепочка (5 из 7 дней с дневной целью) → сундук с наградой.
- Сезонные ивенты (4 раза в год, 2 недели): тематические задания (Ханами, Танабата, Цукими, Новый год) с эксклюзивной косметикой и культурными мини-уроками.

## 8.6. Награды и валюта

- Валюта **«мон»** (文): зарабатывается квестами и достижениями. Тратится на: заморозки, восстановление серии, косметику (темы оформления, иконки профиля, питомец-компаньон тануки/кицунэ с эволюцией от регулярности).
- Покупка валюты за деньги — **исключена** (учебная честность и юрисдикционные риски лутбоксов). Premium даёт +20% к заработку.

# 10. Аналитика обучения

## 10.1. Метрики для пользователя

| Метрика | Представление |
|---|---|
| Выученные слова | Счётчик + динамика; разбивка по стадиям: изучается / закреплено (S>21 дн) / освоено (S>180 дн); по уровням JLPT |
| Выученные кандзи | То же + раздельно по навыкам: значение/чтение/написание |
| Процент правильных ответов | True Retention по дням/неделям; в разрезе типов упражнений и типов контента |
| Время обучения | Мин/день, среднее за неделю, распределение по активностям (SRS/уроки/аудио/ИИ-диалоги) |
| Слабые темы | Топ проблемных зон из классификатора ошибок: «частица に vs で — 38% ошибок», «глаголы 2-й группы», «различение シ/ツ»; каждая зона → кнопка «дрилл» (ИИ-генерация упражнений) |
| Прогноз достижения уровня | «При текущем темпе N4 — к 15 марта 2027»; модель: остаток контента ÷ фактическая скорость освоения (EMA за 28 дней) с доверительным интервалом; при выбранной дате экзамена — обратный расчёт требуемого темпа |
| Скорость чтения | Знаков/мин по результатам типа 52, динамика |
| Сравнение с целью | План vs факт недели (мин, карточки, уроки) |

## 10.2. Продуктовая аналитика (внутренняя)

- События: активации, конверсия онбординга (до первого урока / до 7-го дня), retention D1/D7/D30, длина сессий, churn-предикторы (падение точности, рост просрочки SRS).
- Учебная телеметрия: сложность каждого упражнения по популяции (доля ошибок) → автоматическая пометка плохих заданий на редактуру; A/B-эксперименты на методике (порядок типов упражнений, размер урока).
- Стек: события → Kafka/Redpanda → ClickHouse; дашборды Metabase/Superset. PII отделён от телеметрии (анонимные user_id).

## 11.2. Навигация и ключевые паттерны

- **Правило 2 тапов:** от запуска до начала занятия (кнопка «Начать» на «Сегодня» агрегирует SRS+урок в одну сессию).
- Урок — линейный поток без навигации вглубь; «карточные» экраны (слово/кандзи) — bottom-sheet, чтобы не терять контекст.

| Файлы/медиа | S3-совместимое (Cloudflare R2) + CDN | Аудио, иллюстрации; pre-signed URLs |
| Морфоанализ | Сервис на Python: **Sudachi/MeCab + fugashi** | Токенизация, фуригана-генерация, валидация ИИ-контента; отдельный gRPC-микросервис |
| ASR/TTS | Управляемые API (этап 1), self-hosted Whisper (этап 2) | Время выхода на рынок |
| Телеметрия | Kafka/Redpanda → ClickHouse | Раздел 10.2 |
| Инфраструктура | Docker + Kubernetes (или Fly.io/Railway на старте), Terraform, GitHub Actions CI/CD | |
| Наблюдаемость | OpenTelemetry → Grafana/Loki/Tempo + Sentry | |

Архитектурный стиль: **модульный монолит** с явными границами модулей (auth, content, srs, gamification, ai, billing, analytics) — выделение в сервисы только при доказанной необходимости (первые кандидаты: ai-gateway, морфоанализ).

## 13.2. REST API (v1, фрагмент контракта)

Принципы: OpenAPI-спецификация — источник правды (генерация клиентских SDK), версионирование в пути `/api/v1`, пагинация курсорная, идемпотентность мутаций по `Idempotency-Key`.

```
Auth
  POST   /auth/register | /auth/login | /auth/refresh | /auth/logout
  POST   /auth/oauth/{provider}            # google, apple
  POST   /auth/guest                       # гостевой аккаунт → миграция в полный

Курс и контент
  GET    /courses/{slug}/structure          # юниты+уроки+статусы пользователя
  GET    /lessons/{id}                      # сценарий урока (steps)
  POST   /lessons/{id}/complete             # результат: score, ответы, длительность
  GET    /vocabulary/{id} | /kanji/{id} | /grammar/{id}
  GET    /search?q=…&type=vocab|kanji       # словарный поиск

SRS
  GET    /srs/queue?limit=50                # очередь к повторению (sorted)
  POST   /srs/answers                       # батч ответов [{card_id, rating, duration_ms, …}]
  GET    /srs/forecast?days=30              # прогноз нагрузки
  GET    /srs/stats?period=month
  POST   /srs/cards                         # добавить слово из словаря в SRS
  PATCH  /srs/cards/{id}                    # suspend / reset / bury

ИИ
  POST   /ai/explain                        # {context_type, context_id, question?}
  POST   /ai/feedback                       # разбор свободного ответа
  POST   /ai/conversations  + WS /ai/conversations/{id}/stream   # Кайва-додзё
  POST   /ai/drills/generate                # упражнения по слабым местам

Геймификация / профиль
  GET    /me | PATCH /me | GET /me/stats?period=…
  GET    /me/achievements | /leagues/current | /quests/today
  POST   /quests/{id}/claim

Биллинг
  GET    /billing/plans
  POST   /billing/subscribe                 # web: Stripe/ЮKassa checkout session
  POST   /billing/webhooks/{provider}       # + верификация App Store/Play receipts
```

Ответы SRS принимаются **батчами с клиентскими таймстемпами** — основа офлайн-синхронизации: клиент ведёт локальную очередь (SQLite/Drift), при подключении пушит лог, сервер мёржит по принципу «журнал ответов append-only, состояние карточки пересчитывается из журнала» (конфликтов состояний нет по построению; конфликт двух устройств решается переигрыванием журнала по времени).

## 13.3. GraphQL — нужен ли?

На MVP — **нет**: REST + генерируемые типизированные SDK покрывают потребности, OpenAPI проще кэшировать на CDN. Пересмотр после запуска веба: страницы карточек слова/кандзи агрегируют много связанных сущностей — если профилирование покажет проблему N запросов, добавить GraphQL-шлюз (Apollo/Yoga) **только для чтения контента**, мутации оставить в REST. Решение зафиксировать ADR-документом.

## 13.4. Авторизация и безопасность

- **JWT access** (15 мин, в памяти клиента) + **refresh** (30 дней, httpOnly cookie на вебе / secure storage на мобильных) с ротацией и детекцией повторного использования (reuse → отзыв всей семьи токенов).
- OAuth: Google, Apple (обязателен для iOS). Гостевой режим: полноценный аккаунт без email → мягкая конвертация (прогресс сохраняется).
- Пароли — Argon2id; 2FA (TOTP) — опционально для пользователя.
- Rate limiting (Redis, скользящее окно) per-IP и per-user; для ИИ-эндпоинтов — отдельные квоты по тарифу.
- RBAC: user / moderator / content_editor / admin. Админка контента — отдельное приложение за SSO.
- GDPR/152-ФЗ: экспорт данных (`GET /me/export` → архив), удаление аккаунта (soft → жёсткое через 30 дней), согласия на телеметрию.

## 13.5. Хранение прогресса

- Источник правды — сервер (Postgres). Клиент — полная офлайн-копия учебного состояния пользователя (его карточки, прогресс уроков) + пакеты контента уровня (скачиваются целиком: ~30–60 МБ на уровень с аудио).
- Синхронизация: push журнала ответов (13.2) + pull дельты контента по `version`. Last-write-wins только для настроек.
- Бэкапы: PITR (wal-g), ежедневные снапшоты, restore-тест ежемесячно. Журнал reviews — критические данные (пересоздаёт всё состояние SRS).

## 13.6. Масштабирование

- API stateless → горизонтальное масштабирование за балансировщиком; WebSocket-узлы ИИ-диалогов — отдельный пул со sticky-sessions.
- Postgres: сначала вертикально + read-реплики (тяжёлые чтения: статистика, лидерборды); партиционирование `reviews` и `daily_stats` по времени; контент-таблицы малы и кэшируются целиком (Redis + CDN, т.к. контент одинаков для всех).
- Тяжёлое — в фоновые воркеры: FSRS-оптимизация, агрегаты, генерация ИИ-дриллов, обработка аудио.
- Целевые SLO: p95 GET < 150 мс, p95 POST /srs/answers < 250 мс, доступность 99.9%. Нагрузочное тестирование к запуску: 10k RPS на чтение контента (k6).

# 14. Frontend

## 14.1. Сравнение вариантов

| Критерий | Flutter | React Native | Next.js (веб) | Нативная пара (Swift/Kotlin) |
|---|---|---|---|---|
| Канва рукописного ввода (критично!) | ★★★ собственный рендер Skia, идеальный контроль латентности | ★★ через Skia-модуль, сложнее | ★★ Canvas API ок на десктопе | ★★★ |
| Рендер японской типографики, руби/фуригана | ★★★ единый на всех ОС | ★★ зависит от платформенных view | ★★★ HTML `<ruby>` нативно | ★★★ |
| Один код iOS+Android+(веб) | ★★★ | ★★☆ | веб-only | ✗ две команды |
| Скорость разработки/найм (RU/CIS) | ★★★ | ★★☆ | ★★★ | ★☆ |
| Анимации, 120 fps | ★★★ | ★★ | ★★ | ★★★ |
| SEO/шаринг контента | ✗ (Flutter Web слаб для SEO) | ✗ | ★★★ | ✗ |
| Размер бандла | ~15 МБ базово | меньше | — | минимальный |

## 14.2. Решение

**Мобильные приложения — Flutter** (iOS + Android из одной кодовой базы). Решающие факторы: канва написания кандзи с проверкой черт — это кастомный рендеринг, где Flutter сильнее всего; пиксельная идентичность японской типографики на обеих платформах; одна команда.

**Веб — Next.js (React, App Router)**: маркетинг + публичные SEO-страницы словаря/грамматики (органика — ключевой канал) + полнофункциональное веб-приложение для занятий с клавиатурой. Клавиатурный ввод каны и десктопная статистика — сценарии, где веб честно лучше мобайла.

Связующее: дизайн-токены из одного источника (11.3); типизированные API-клиенты генерируются из OpenAPI для Dart и TS; учебная логика, которую нельзя дублировать (FSRS-расчёты, валидация ответов), живёт **на сервере** — клиенты тонкие, расхождение платформ исключено по построению. Состояние: Flutter — Riverpod + Drift (офлайн SQLite); Next.js — TanStack Query + Zustand.

React Native — резервный вариант, если команда окажется React-центричной; нативная пара отвергнута по стоимости.

# 16. MVP

**Цель MVP:** доказать core loop — «пользователь с нуля осваивает кану и начинает N5, возвращается ежедневно ради SRS». Метрики успеха: D7 retention ≥ 25%, D30 ≥ 12%, медиана сессии ≥ 8 мин, ≥ 35% дошедших до конца хираганы.

## 16.1. Объём MVP (Must — MoSCoW)

- Платформы: **Flutter-приложение (iOS + Android)** + лендинг. Веб-приложение — после MVP.
- Аккаунты: email + Google/Apple, гостевой режим.
- Контент: хирагана + катакана полностью; **N5: первые 6 юнитов** (~60 уроков, ~400 слов, ~60 кандзи, ~45 грамматик).
- SRS на FSRS (глобальные веса, без персональной оптимизации), лимиты, базовая статистика (очередь, retention, heatmap).
- **18 типов упражнений** (ядро): №№ 1–5, 7, 8, 10–12, 18, 20, 21 (написание — режим «Обучение»), 27–29, 34, 37.
- Рукописный ввод каны и кандзи с проверкой черт (режимы обучение/стандарт).
- ИИ v1: объяснение ошибок (фича-флаг, квоты) — одна функция, доведённая до ума.
- Геймификация v1: XP, серия с заморозками, 25 достижений, дневная цель. Без лиг.
- Биллинг: подписка Premium (Stripe/ЮKassa + App Store/Play), триал.
- Офлайн: SRS-сессии и пройденные уроки без сети, синхронизация журналом.

**Should (если успеваем):** аудио-упражнения 38–40, подкаст-режим (5 историй), словарный поиск по JMdict, тёмная тема.
**Could:** питомец, лиги, ИИ-диалоги.
**Won't (в MVP):** N4+, веб-приложение, произношение/ASR, B2B, пробные JLPT, GraphQL.

## 16.2. Команда и сроки

Команда: 2 Flutter, 2 backend, 1 fullstack (админка контента + лендинг), 1 дизайнер, 1 методист-японист + 1 контент-редактор, 0.5 PM, 0.5 QA.

| Фаза | Срок | Результат |
|---|---|---|
| 0. Дизайн-спринт + контент-пайплайн | нед. 1–4 | Дизайн-система, прототип, схема БД, админка контента v0, первые 2 юнита контента |
| 1. Ядро | нед. 5–12 | Auth, курс-движок, 18 упражнений, SRS, рукописный ввод; внутренняя альфа |
| 2. Обвязка | нед. 13–17 | Геймификация, ИИ-объяснения, биллинг, офлайн-синхр., полировка; закрытая бета (300–500 чел.) |
| 3. Бета и запуск | нед. 18–22 | Итерации по метрикам беты, контент до 6 юнитов N5, сторы, маркетинг-подготовка |

**Итого до публичного запуска: ~5 месяцев.** Контент-производство идёт параллельно всем фазам и является главным риском срока → админка контента строится в фазе 0.

## 16.3. Приоритезация при срыве сроков

Режутся в порядке: ИИ-объяснения → часть достижений → катакана-«ад»-дриллы → офлайн (остаётся read-only кэш). **Не режутся никогда:** SRS, рукописный ввод, качество контента, биллинг.

**Поток данных core loop:** клиент тянет SRS-очередь и контент-пакет → пользователь отвечает (офлайн допустим) → журнал ответов батчем в Core API → пересчёт FSRS-состояния карточек → событие в аналитику → ошибки классифицируются (правила + ИИ) → карта слабых мест → AI-Gateway генерирует персональные дриллы → они появляются в завтрашней очереди. Круг замкнут: каждое действие пользователя улучшает его персональный план.

## Приложение А. Глоссарий
JLPT — Japanese Language Proficiency Test (N5 — начальный … N1 — высший). SRS — spaced repetition system. FSRS — Free Spaced Repetition Scheduler (DSR-модель). Фуригана — подсказки чтения каной над кандзи. Онъёми/кунъёми — китайские/японские чтения кандзи. Кейго — система вежливой речи. Мора — ритмическая единица японского. Питч-акцент — тоновое ударение. i+1 — ввод чуть выше текущего уровня (Krashen). Gate-тест — тест-«ворота» юнита.
