# Проверка UI

Headless-прогон веб-интерфейса через Chrome/Edge (CDP). Скрипт самодостаточен:
сам находит браузер и сам поднимает сервер, если тот не запущен.

## Шаги

1. Запусти прогон (из корня проекта):

   ```
   .venv\Scripts\python scripts\ui_check.py
   ```

   Скрипт печатает диагностику и в конце блок `=== ИТОГ ===`:
   - `OK — проблем не найдено` (exit 0), либо
   - `ПРОБЛЕМЫ (N):` со списком (exit 1).

2. Прочитай свежие скриншоты в корне проекта инструментом Read (это PNG —
   видно глазами). Снимаются:
   - `shot_m_today.png` — «Сегодня» (мобильный 390px)
   - `shot_m_lessons.png` — «Путь» (сетка уроков)
   - `shot_m_exercise.png` / `shot_m_exercise_answered.png` — упражнение
     до и после ответа (проверка балансировки и отсутствия «прыжка»)
   - `shot_m_settings.png` — настройки (тумблеры, селекторы)
   - `shot_d_today.png` — «Сегодня» на десктопе (1100px)

3. Соотнеси числа из вывода с задачей:
   - `JS errors` — должно быть `(none)`;
   - `overflow … scrollWidth == vw` — без горизонтального переполнения;
   - `layout shift … = 0px` — варианты ответа не прыгают при ответе;
   - `sound decode` — звук нажатия декодируется (Web Audio).

4. После анализа удали временные скриншоты — они в .gitignore, но не нужны:

   ```
   rm -f shot_*.png
   ```

## Заметки

- Упражнение-выбор рендерится **синтетически** (`runChoice` без сохранения),
  поэтому прогон НЕ пишет ответы в `michi.db` и не трогает прогресс.
- Чтобы добавить/изменить снимаемые экраны или замеры — правь
  `scripts/ui_check.py` (там же зашиты грабли headless-скриншотов на Windows:
  абсолютный путь, классический `--headless`, fire-and-forget для сессий).
- Нужен пакет `websockets` (есть в `requirements-dev.txt`).
